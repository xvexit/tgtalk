# Roadmap

Каждый этап: цель, в рамках, вне рамок, критерий готовности (команда). Этапы идут строго по порядку.

## Этап 0. Каркас
**Цель:** репозиторий, Docker, контракты, пайплайн на заглушках.
**В рамках:** `pyproject.toml`, Dockerfile, `docker-compose.yml` (bot + db с pgvector), `.env.example`, `.gitignore`;
`core/` (модели, Protocol, Pipeline), `llm/fake.py`, `FakeSender`; Alembic + первая миграция (`messages`, `contacts`, `groups`, `personas`, `reply_log`);
ruff, mypy, pytest.
**Вне рамок:** Telegram, DeepSeek, RAG.
**Готово, когда:** `docker compose up -d db` поднимается; `alembic upgrade head` проходит; `pytest` зелёный; `ruff check` и `mypy src/tgtwin/core` без ошибок;
тест прогоняет `IncomingMessage` через Pipeline на заглушках и получает `reply`.

## Этап 1. Telegram + dry-run
**Цель:** связка с реальным Telegram без отправки.
**В рамках:** адаптер aiogram, `business_connection`/`business_message`, `Record`, `GuardOwner`, `GuardTakeover`, эхо-фильтр, `Sender` с `SEND_ENABLED=false`, уведомление владельца об отключении.
**Вне рамок:** реальная LLM, отправка.
**Готово, когда:** `docker compose up -d`; сообщение в подключённый чат появляется в `messages`; в логе видно «ответил бы»; в чат ничего не отправлено;
твоё ручное сообщение записывается как `owner`; уведомление приходит при отключении подключения.

## Этап 2. Первый реальный ответ
**Цель:** DeepSeek отвечает, отправка включается на одном чате.
**В рамках:** `OpenAICompatProvider`, `BuildContext` (персона + последние N), `LLMStep` с `[ESCALATE]`, `Postprocess` (задержка, typing), `log_reply`, включение `SEND_ENABLED=true`.
**Вне рамок:** RAG, профили контактов.
**Готово, когда:** юнит-тесты на `LLMStep` с фейковым провайдером; в одном выбранном чате бот отвечает; эскалация приходит владельцу; все ответы видны в `reply_log`.

## Этап 3. Ingestion и оценочный стенд
**Цель:** загрузка экспорта и измеримое качество.
**В рамках:** парсер `result.json`, разметка ролей, нарезка на диалоги, идемпотентная загрузка в БД (CLI-команда), отложенная выборка, `eval` (прогон + метрики).
**Вне рамок:** эмбеддинги, подмешивание примеров в бота.
**Готово, когда:** `docker compose run --rm bot python -m tgtwin.ingestion <file>` загружает реальный экспорт без падений, повторный запуск ничего не дублирует;
`python -m tgtwin.eval` выдаёт отчёт с метриками для базовой версии (этот отчёт — точка отсчёта).

## Этап 4. RAG, профили стиля, правила по контактам
**Цель:** «звучит как я», разное поведение для разных людей.
**В рамках:** выбор и подключение эмбеддера, таблица `chunks` (pgvector), индексирование, `RetrieveExamples`, `StyleProfiler` (глобальный и по контакту), `resolve_config` с группами/контактами/персонами, CLI для управления контактами.
**Вне рамок:** режим draft, медиа.
**Готово, когда:** стенд показывает улучшение метрик относительно этапа 3; контакту можно сменить персону/режим строкой в БД без правки кода и перезапуска логики.

## Этап 5. Защиты и управление
**Цель:** безопасная долгая эксплуатация.
**В рамках:** расписание, лимиты частоты, эскалация по темам (деньги, личное, «срочно»), команды управления в чате с ботом (`/pause`, `/mode`, `/why`), режим `draft` с кнопками.
**Готово, когда:** `/why` показывает контекст и примеры последнего ответа; `/pause` мгновенно останавливает автоответы; тесты на каждый guard.

## Этап 6. Расширения (по желанию)
Медиа и голосовые, перенос на VPS, локальная LLM, файнтюн, другие мессенджеры.
